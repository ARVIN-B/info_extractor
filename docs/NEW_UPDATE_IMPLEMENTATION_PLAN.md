# برنامهٔ اجرای ارتقای جدید

## وضعیت بررسی پیش از تغییر

- معماری موجود: Django templates و ORM، Celery، MCP stdio client، رجیستری ابزارها و Adapterهای اختصاصی در `leads/`؛ SQLite تنظیم‌شده و مهاجرت‌ها تا شمارهٔ 0006.
- جریان Job: view رکورد و SourceExecutionها را ایجاد می‌کند؛ `run_search_job` هر منبع را ترتیبی اجرا می‌کند؛ `execute_source` داده را در همان لحظه ذخیره می‌کند؛ موفقیت منبع قبلی هنگام بازیابی دوباره اجرا نمی‌شود.
- نقص‌های قطعی: fair-share با Exception عمومی ثبت می‌شود؛ زمان cooldown در `sources.py` به ۳۶۰۰ ثانیه بریده می‌شود؛ cooldown میان workerها تنها از DB خوانده می‌شود؛ retry وضعیت retry-after را از نتیجهٔ پاسخ استخراج نمی‌کند؛ Evidence خام با هر بار اجرای دوباره تکرار می‌شود؛ پایان عادی بودجه/محدودیت منبع در جمع‌بندی Job خطا شمرده می‌شود.
- محدودیت منابع جدید: رجیستری پنج منبع دارد. Torob، Digikala، SnappShop و Iran Jobs در کاتالوگ رسمی مخزن پیشنهادی ثبت‌اند؛ جست‌وجوهای فروشگاهی محصول/فروشنده می‌دهند و تضمین تلفن یا وب‌سایت رسمی ندارند. Iran Jobs برای شناسایی شرکت کارفرما، دادهٔ مرتبط‌تری دارد. ادغام خروجی‌ها باید با نوع داده و provenance همراه باشد.
- فایل‌های بررسی‌شده: `models.py`, `mcp_client.py`, `adapters.py`, `sources.py`, `tasks.py`, `normalization.py`, `views.py`, `forms.py`, `tests.py`, `settings.py`, `.env.example`, `requirements.txt`, migrations و قالب‌های جست‌وجو/جزئیات/نمایش Lead.
- وضعیت Git پیش از تغییر: فقط `docs/new_update.md` فایل تازهٔ کاربر بود؛ دست‌نخورده می‌ماند.

## شواهد نهایی

- `.venv\\Scripts\\python.exe manage.py test leads --verbosity 1`: ۵۳ تست موفق.
- `.venv\\Scripts\\python.exe manage.py makemigrations --check --dry-run`: تغییر migration جامانده پیدا نشد.
- `.venv\\Scripts\\python.exe manage.py check`: بدون خطا.
- پنج بستهٔ افزوده با `pip show` از مسیر `.venv\\Lib\\site-packages` تأیید شدند؛ نصب سراسری انجام نشده است.
- قرارداد `list_tools()` برای پنج MCP جدید بررسی شده و در `SOURCE_CATALOG_AUDIT.md` آمده است. جست‌وجوی زنده در وب‌سایت‌های منبع اجرا نشده؛ دسترسی، محدودیت جغرافیایی/شبکه و نرخ پاسخ آن‌ها در محیط استقرار اثبات نشده است.
- برای Windows: `.venv\\Scripts\\python.exe -m pip install -r requirements.txt` و سپس `.venv\\Scripts\\python.exe manage.py migrate`.
- برای Linux: `./.venv/bin/python -m pip install -r requirements.txt` و سپس `./.venv/bin/python manage.py migrate`.

## تصمیمات اجرا

- وابستگی جدیدی فقط پس از تأیید قرارداد و اجرای آن در `.venv` نصب می‌شود؛ نصب سراسری انجام نمی‌شود.
- جست‌وجوی آنلاین منبع اختیاری CI نیست. Smoke test زنده فقط در صورت تنظیم شبکه/خروجی مجاز و به‌صورت صریح انجام می‌شود.
- نقشه و SQLite حفظ می‌شوند؛ تغییرات دیتابیس فقط migration افزایشی خواهند داشت.
- منابع محصولی به‌عنوان «کشف فروشندهٔ بازارگاه» برچسب می‌خورند و از دادهٔ محصول به‌تنهایی شماره یا وب‌سایت رسمی جعل نمی‌شود.
