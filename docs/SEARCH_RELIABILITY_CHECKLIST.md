# چک‌لیست اصلاح جست‌وجو

## بررسی و اصلاح

- [x] بررسی فرایند وب روی `127.0.0.1:8000`، تنظیمات `.env`، وضعیت Redis، صف و jobهای SQLite.
- [x] پیدا کردن ناهماهنگی تنظیم broker فرایند وب با worker و افزودن broker فایل‌محور مخصوص توسعهٔ محلی.
- [x] تطبیق جست‌وجوی صنف بلد با ابزار واقعی `bl_nearby`؛ نگه‌داشتن `bl_search` برای resolve کردن مکان.
- [x] جداکردن عبارت صنف از شهر در جست‌وجوی نشان و resolve کردن غلط املایی کوچک در نام شهر.
- [x] نرمال‌سازی پسوند جمع فارسی و ساخت عبارت عمومی فروشگاه برای صنف‌های جدید.
- [x] حذف نتیجه‌های نامرتبط بر پایهٔ نام/دسته‌بندی همان رکورد و نشان‌دادن پیام روشن برای نتیجهٔ خالی یا job ناموفق.
- [x] اصلاح decoder خطای MCP برای هر دو نام فیلد `isError` و `is_error`؛ توقف جزئیات بیشتر پس از اولین HTTP 429 و حفظ نتیجهٔ جست‌وجو.
- [x] افزودن regression test برای ابزار بلد، دسته‌های ناآشنا، غلط شهر و relevance.
- [x] حذف مقدارهای تلفن خالی و canonical کردن املای شهر در دادهٔ job.
- [x] اجرای ۲۹ آزمون، `manage.py check`، بررسی migrationها و `pip check`.

## آزمون زنده

- [x] ثبت جست‌وجوی واقعی HTTP با «شیشه فروشی‌های اصفها»: job با نام اصلاح‌شدهٔ «اصفهان» و ۶۷ کسب‌وکار یکتا از ۱۱۰ نتیجهٔ خام کامل شد؛ ۳۹ کسب‌وکار تلفن معتبر و ۴۰ وب‌سایت داشتند.
- [x] اجرای جست‌وجوی واقعی متنوع «کافه» در تهران: ۹ کسب‌وکار یکتا، هر ۹ دارای تلفن معتبر و وب‌سایت؛ هر دو منبع موفق شدند.
- [x] بازبینی HTTP صفحهٔ job و خروجی‌ها: صفحه، JSON و Excel همگی status 200؛ JSON شامل ۶۷ نتیجه و فایل Excel امضای معتبر XLSX داشت.
- [x] پاک‌کردن jobهای آزمایشی ناموفق/نویزدار؛ jobهای نهایی ۱۱ و ۱۲ در تاریخچهٔ حساب باقی ماندند.
